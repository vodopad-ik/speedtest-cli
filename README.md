# speedtest-cli

Консольный скрипт на Node.js, который замеряет скорость скачивания по HTTP(S).
Делает N запросов к указанному адресу **строго последовательно**, каждый раз дочитывает ответ до конца и выводит среднее время запроса, общий объём скачанных данных и скорость.

Внешних зависимостей нет — только встроенные модули Node.js (`fetch`, `node:util`, `node:test`).

## Требования

- Node.js **18.3+** (проверено на Node.js 24)

## Запуск

```bash
git clone https://github.com/<username>/speedtest-cli.git
cd speedtest-cli

node bin/speedtest.js https://proof.ovh.net/files/10Mb.dat
```

`npm install` не нужен. Через npm тоже можно:

```bash
npm start -- https://proof.ovh.net/files/10Mb.dat
```

### Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `-n`, `--count <число>` | `10` | сколько запросов сделать |
| `-t`, `--timeout <сек>` | `30` | таймаут одного запроса |
| `-h`, `--help` | | справка |

Тестовые файлы, на которых удобно проверять: `https://proof.ovh.net/files/10Mb.dat`, `https://proof.ovh.net/files/100Mb.dat`.

## Единицы измерения

- **Скорость — `Mbit/s` (мегабиты в секунду)**, в скобках дублируется в `MB/s` (мегабайты в секунду). Мегабиты выбраны потому, что в них указывают тарифы провайдеры и показывает speedtest.net — так результат легко сравнить.
- **Объём — `MB`**, **время — `ms`**.
- Все единицы **десятичные (SI)**: `1 MB = 1 000 000 байт`, `1 Mbit/s = 1 000 000 бит/с`, `1 байт = 8 бит`.
  Поэтому файл `10Mb.dat` (это 10 MiB = 10 485 760 байт) отображается как `10.49 MB`.

## Как считается

- **Время запроса** — от отправки запроса до получения последнего байта тела (`process.hrtime.bigint()`, монотонные часы). В него входят DNS, установка соединения, ожидание ответа и скачивание.
- **Объём** — реально полученные байты тела, посчитанные по чанкам потока. На `Content-Length` не опираемся: его может не быть (chunked-ответ) или он может не совпадать с телом.
- **Среднее время** — сумма времени успешных запросов / их количество.
- **Скорость** — `(все байты × 8) / всё время`. Не среднее из скоростей отдельных запросов: иначе один нетипично быстрый или медленный запрос перекосил бы итог.
- Чтобы замер был честным, запросы отправляются с заголовками:
  - `Cache-Control: no-cache` — чтобы CDN/прокси не отдавали ответ из кеша;
  - `Accept-Encoding: identity` — чтобы сервер не сжимал ответ. Иначе `fetch` распаковал бы gzip/br и мы посчитали бы распакованный объём вместо скачанного.

### Обработка ошибок

- Ответ не 2xx, таймаут, сетевая ошибка — запрос помечается как ошибочный, замер продолжается, в итог попадают только успешные запросы.
- Коды выхода: `0` — был хотя бы один успешный запрос, `1` — все запросы упали, `2` — неверные аргументы. Поэтому скрипт можно запускать в CI или по крону.

### Что видно на реальных данных

Первые 2–3 запроса обычно медленнее остальных. Это нормально: первый запрос тратит время на DNS и TLS-рукопожатие, а TCP в начале соединения разгоняется постепенно (slow start). Дальше `fetch` переиспользует keep-alive соединение, и скорость выходит на плато.

## Тесты

```bash
npm test
```

Тесты поднимают локальный HTTP-сервер (интернет не нужен) и проверяют: что делается ровно N запросов, что байты считаются корректно в том числе без `Content-Length`, обработку 404 и таймаута, формулу скорости и валидацию аргументов.

```
src/format.js        — форматирование единиц
test/measure.test.js — тесты
```
